# 服务器故障运维手册

## Q: 服务器 CPU 持续 90% 以上怎么排查？

**结论**：先定位高 CPU 进程，再判断是否为批任务、发布变更或异常循环导致。

**排查步骤**：
1. 执行 top 或 ps aux --sort=-%cpu 查看占用最高的进程
2. 核对是否刚发布版本或批对账/ETL 任务与业务高峰重叠
3. 检查 /var/log 是否因 debug 日志暴涨导致 IO 等待间接拉高 CPU
4. 若为 Java 进程，导出线程栈 jstack 分析是否死循环

**升级条件**：CPU 持续 30 分钟超 90% 且影响核心交易，升级二线并考虑临时限流。

## Q: Linux 服务器内存不足触发 OOM 怎么办？

**结论**：OOM 说明物理内存或 swap 耗尽，需定位内存泄漏或大对象进程。

**排查步骤**：
1. 查看 dmesg | grep -i oom 确认被 kill 的进程
2. free -h 与 cat /proc/meminfo 查看可用内存
3. 对疑似进程做 pmap 或 jmap（Java）分析堆使用
4. 评估是否可调低 JVM 堆或迁移批任务

**升级条件**：同一进程反复 OOM，升级应用负责人与系统工程师。

## Q: 日志盘 /var/log 使用率超过 85% 如何处理？

**结论**：多为日志级别过高或未按策略切割归档。

**排查步骤**：
1. du -sh /var/log/* 找出最大目录
2. 检查应用 log level 是否误设为 DEBUG
3. 执行 logrotate 或清理 30 天前归档
4. 评估是否扩容或挂载独立日志盘

**升级条件**：磁盘使用率 > 95% 且无法快速释放，启动应急扩容流程。
